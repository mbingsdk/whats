# ADR 003: SSE plus REST

Use SSE for server-to-browser projections/invalidation; use REST for commands and throttled presence/typing heartbeats. Current product traffic is predominantly server push, so bidirectional WebSocket commands add protocol/auth/recovery work without a demonstrated requirement.

Tradeoffs: SSE uses ordinary HTTP/session authorization and a simple reconnect model, but requires Nginx buffering configuration, bounded replay and connection management. WebSocket offers efficient bidirectional traffic but still needs per-event authorization, resume and backpressure. Neither provides durable delivery by itself.

Durable per-organization publication cursors and resource revisions support recovery; events filter by current access. Ephemeral presence is not replayed. Cross-tab multiplexing reduces connection overhead. REST remains authoritative after gaps.

Revisit for verified Calling signaling or measured high-rate bidirectional interactions. Do not replace this with a WebSocket solely because the inbox is described as realtime.
