# Identity runtime, sessions and mail

Status: implementation decision within authorized Sprint 1, 2026-09-10. Refines [tenant isolation](005-tenant-isolation.md) and [secret encryption](006-secret-encryption.md); no Meta gate changes.

The API has two limited PostgreSQL pools. waba_runtime retains the foundation organization boundary and cannot read global users. waba_identity owns no tables and cannot assume migrator/authorizer roles, but may read/update global identity records because login precedes organization selection. Its organization-owned tables still FORCE RLS. The mail worker uses the same identity privilege boundary for global identity mail and explicitly scoped invitation jobs. This is a documented trusted-service exception, not a tenant-header shortcut.

Password authentication uses the maintained Go Argon2id implementation; opaque session, CSRF, action and recovery tokens are random and stored as digests. A session is an authenticated global principal plus optional selected organization and membership access revision. Every request checks global status/auth revision, expiry and organization access revision; organization operations additionally hold the shared/exclusive organization barrier. Changed grants or offboarding invalidate affected organization sessions. The actor receives a rotated cookie only if still active. Cookie rotation cannot extend the original absolute deadline or refresh reauthentication without a real credential proof.

Role authorization uses explicit permission keys and ORG/TEAM/SELF resources, never role-name branches. Bootstrap names Owner/Admin/Agent are only presets. Multiple direct scoped grants and team inheritance combine; delegation is limited to the actor's current scope. Role/team writers lock the organization before grant changes and enforce a remaining active organization-wide owners.manage grant. Per-user locks serialize identity changes; invitation acceptance locks discovered user principals in ID order before the organization. This simple ordering is appropriate for identity administration; it is not evidence for future dispatch capacity.

Per-secret AEAD envelopes protect TOTP seeds and the minimum SMTP payload. Root keys live outside PostgreSQL; losing a key requires recovery, never silent generation against existing data. One-use links use fragments and explicit completion POSTs. Existing-identity invitations require an authenticated matching account and session CSRF proof; invitation evidence cannot replace a password. Password/MFA changes revoke pending login-MFA challenges.

A PostgreSQL mail outbox commits with the initiating identity transaction. A separate worker claims with SKIP LOCKED and a fenced two-minute lease, sends outside the transaction with a 90-second maximum, and records a sanitized terminal/retry result. Up to eight attempts are allowed within 24 hours and the original source deadline. Ambiguity may produce duplicate email with the same link/Message-ID; it never permits automatic ambiguous WhatsApp retries. Completed attempts are immutable; terminal payloads are purged. SMTP acceptance is distinct from controlled inbox receipt.

Tradeoffs: compromised identity-service credentials can access global identity data; RLS is defense in depth, not protection against a compromised trusted host. The same service privilege boundary is intentionally used by API and mail worker initially; production process users and secret file access are still separated from frontend/build/migration. Root-key rotation, external alert routing and real mailbox receipt require operational procedures/evidence before production. Gates B/C/D remain CLOSED.
