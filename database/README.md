# Database and migration conventions

PostgreSQL 18.6 is pinned by digest in [Compose](../compose.yaml). Run python scripts/dev.py up. Local setup creates waba_migrator, waba_runtime, NOLOGIN waba_authorizer and the Sprint 1 waba_identity role. Existing volumes are retained; up applies the idempotent identity-role setup for volumes initialized during Sprint 0. Passwords and the identity root key remain in ignored protected files. Missing existing credentials or root keys require recovery.

Run python scripts/dev.py migrate using waba_migrator. Goose 3.28.0 and pgx 5.11.0 use a PostgreSQL advisory migration lock. API startup never migrates. A successful repeated application changes zero migrations. The current binary requires schema version 2 exactly; older/newer schemas fail readiness. Rollback from version 2 to the Sprint 0 binary is incompatible unless a separately tested compatibility release is provided.

Published 00001_identity_tenants.sql is unchanged. New 00002_identity_access.sql adds passwords, sessions, challenges, TOTP/recovery, limits, roles/grants, invitations, teams, audit and durable identity mail. See [physical schema and evidence](../docs/24-sprint-1-evidence.md). Update manifest.sha256 only while reviewing an unpublished migration. Published SQL/checksums are immutable; Down intentionally fails and repair is forward-only. Destructive changes require expand/backfill/contract planning and backup evidence.

All nine new organization-owned tables use FORCE RLS and composite organization FKs. Missing scope denies reads/writes. Organization/member rows retain their original boundary. waba_runtime cannot access global users/passwords/sessions; waba_identity has the explicit global auth/mail exception and scoped tenant access. Neither runtime role owns tables, bypasses RLS, creates roles/schemas or assumes migrator/authorizer. Audit privileges are SELECT/INSERT; completed mail attempts are immutable.

Narrow SECURITY DEFINER functions owned by NOLOGIN waba_authorizer route invitation digests and authenticated user memberships, with fixed SQL/search_path and no public EXECUTE. Only internal authenticated user IDs reach membership authorization. The identity service locks user principals before the shared/exclusive organization barrier and sets the transaction-local scope. Commit/rollback resets pooled context. RLS does not protect against fully compromised trusted service credentials; application authentication and permission checks remain mandatory.

Integration tests create random disposable databases, apply the same reviewed migrations, seed synthetic fixtures via a separate setup administrator, assert through real runtime roles and drop only the isolated test database. Explicit integration runs fail rather than skip when PostgreSQL/configuration is absent. Setup/migration URLs do not enter the API or frontend process. Linux race checks run the same integration packages.

Initial Owner provisioning is an audited operator command, not a migration seed or web signup. Follow the [bootstrap/SMTP runbook](../docs/16-deployment.md#sprint-1-identity-operations). The singleton prevents duplicate bootstrap. Global suspension/auth revisions and membership access revisions invalidate sessions without deleting identity/audit history. Local Docker volume persistence is not a backup.

Publication erratum: the Sprint 1 00002 manifest was computed from CRLF working bytes before Git normalized the published SQL to LF. Both published files remain unchanged. checksum-corrections.json pins the exact published LF artifact with source-commit provenance; source validation requires that digest and rejects CRLF or changed SQL. See the [CI correction evidence](../docs/24-sprint-1-evidence.md#published-sprint-1-ci-correction-2026-09-10). New migrations still require their own manifest entry.
